# 기존 트럭 앱 키를 쓰는 AI 상담 연결안

모아 운영 서버에는 `OPENAI_API_KEY`가 없습니다. 트럭 앱의 Supabase 프로젝트 `truck-driver-production` (`xyznywfrqfqmfcxcihkx`)의 기존 함수에서 `FORTUNE_OPENAI_API_KEY`를 읽어 GPT-6.1 Terra를 호출하는 것을 확인했습니다. 해당 키의 실제 값은 읽거나 내보내지 않았습니다.

이 변경은 기존 키가 보관된 런타임에 모아 전용 `moa-advisor-relay` 함수를 추가하고 모아 서버가 그 함수만 호출하는 방식입니다. OpenAI 키를 다른 저장소나 고객 브라우저에 복사하지 않습니다. 모아에 새 OpenAI 키를 발급하는 변경도 아닙니다. 배포와 서버 설정은 별도 승인을 받은 뒤 진행합니다. 실제 OpenAI 응답은 아직 검증되지 않았습니다.

## 호출 경로와 접근 범위

1. 고객은 기존 모아 로그인 후 `/api/advisor`를 호출합니다. 모아는 본인 계정의 revision, 동일 출처, 일일 사용량과 동시 요청 제한을 검증합니다.
2. 모아 서버는 비밀 환경변수 `ADVISOR_RELAY_TOKEN`을 `Authorization: Bearer` 헤더로 보냅니다. URL은 `ADVISOR_RELAY_URL`이며 허용된 HTTPS Supabase 함수 경로만 사용합니다. 고객은 이 설정을 바꿀 수 없습니다.
3. 새 Supabase 함수는 인터넷에서 도달 가능한 주소를 갖지만, 유효한 모아 전용 256비트 서비스 토큰 없이는 키를 읽거나 OpenAI를 호출하지 않습니다. 플랫폼의 Supabase 사용자 JWT 검증은 이 함수에 한해 끄고 함수 자체의 전용 서비스 인증으로 대체합니다. 다른 트럭 앱 함수의 인증은 바꾸지 않습니다.
4. 함수 소스에는 토큰의 SHA-256 검증값만 둡니다. 원본 서비스 토큰은 모아의 서버 비밀 설정에만 저장하며, OpenAI 키는 기존 Supabase 비밀 설정에 남습니다.
5. 함수는 기존 `FORTUNE_OPENAI_API_KEY`로 OpenAI Responses API를 호출합니다. 모델 `gpt-6.1-terra`, 추론 `xhigh`, `store:false`를 고정하고 도구·스트리밍·모델 변경 요청은 거절합니다. 입력 64KiB, 출력 상한 16,384토큰, 상위 응답 대기 140초로 제한합니다.

모아 상담에 쓰던 계정별 자산 요약과 질문만 전달합니다. 트럭 앱의 장부·사용자 테이블·권한·기존 함수는 읽거나 변경하지 않습니다. 요청 본문과 키를 로그에 기록하지 않고 제공자 오류 메시지 대신 안전한 오류 코드만 반환합니다. API 사용료는 기존 키의 OpenAI 프로젝트에 청구됩니다. 기존 모아의 계정별 하루 10회·전체 하루 100회 제한을 유지합니다.

## 배포 대상

- Supabase: 프로젝트 `xyznywfrqfqmfcxcihkx`, 새 함수 `moa-advisor-relay`, `verify_jwt=false` 및 함수 내부 서비스 인증.
- 모아: 기존 운영 사이트 `appgprj_6afaa4efde9081919728c1a62b3f46fc`의 두 서버 환경변수만 추가하고 해당 코드 버전을 배포합니다. 자산 DB는 바꾸지 않습니다.
- 기존 트럭 앱 함수와 Supabase 프로젝트 비밀값은 수정하지 않습니다. 새 함수의 키 참조 변수명은 `FORTUNE_OPENAI_API_KEY`입니다.

## 검증과 운영

인증 없는 요청·잘못된 토큰·브라우저 Origin은 거부하고, 인증 확인 전에 OpenAI 키를 읽지 않는지 검사합니다. 모델·추론·보관·도구 변경, 잘못된 JSON·과대 요청, 제공자 오류에서의 키 노출, 미등록/잘못된 중계 주소, 고객의 설정 변경을 검증합니다. 기존 직접 키 연결도 유지합니다.

전체 테스트 166개와 Worker 빌드·문법·diff 검사를 통과했습니다. 배포 후 인증된 구성 확인과 가상 데이터로 실제 Terra/xhigh 응답을 검증한 뒤 모아의 서버 설정을 활성화해야 합니다. 인증된 상태 응답만으로 모델 권한·잔액·실제 추론 성공을 단정하지 않습니다.

서비스 토큰을 교체하려면 새 토큰과 그 SHA-256 검증값으로 함수를 갱신하고 모아의 비밀 환경변수를 바꿉니다. OpenAI 키 교체는 기존 Supabase 비밀 설정에서 처리하며 키를 출력하는 진단 경로를 만들지 않습니다.


## 2026-11-18 · 현재 자산 예측·상담과의 호환성

현재 main을 병합해 모바일의 일반 자산 상담과 기존 대출 상환 비교를 모두 지원합니다. 중계 함수의 고정 모델·xhigh·store:false·서비스 인증·입출력 제한은 그대로이며, 응답 형식 이름으로 기존 repayment_advice와 새 asset_advice만 허용합니다. 일반 자산 상담에는 모아 서버가 로그인 계정의 포트폴리오에서 계산한 월말·급여일 전망과 제한된 최근 대화를 전달합니다.

실제 함수 배포나 모아 서버 비밀 설정은 아직 적용하지 않았습니다. 225개 테스트와 Worker 빌드로 현재 main과의 호환성, 두 상담 모드의 서버→중계→가상 제공자 응답 경로를 확인했습니다. 실제 OpenAI 모델 접근 권한·사용 한도·응답은 배포 승인 후 따로 검증해야 합니다. 기존 키를 새 함수에서 쓰는 접근 범위 확장에 대한 승인이 필요합니다.
