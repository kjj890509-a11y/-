# 통합 입력·수정

기존 통합 입력은 새 내역을 연속 등록하는 화면이었으며 이전 방문에서 저장한 내역은 별도 목록을 찾아야 했습니다. `#entry`를 유지하면서 **통합 입력·수정**으로 바꾸고, 기본 화면에 기존 내역 수정 작업공간을 제공합니다.

## 기존 내역 수정

- 전체 또는 수입·지출, 정기 지출, 예금·현금, 주식, 퇴직금·연금, 대출, 카드로 좁혀 봅니다. 이름·기관·메모 검색, 이름/금액 정렬, 변경된 내역만 보기를 지원합니다.
- 표의 셀에서 이름·금액·날짜·메모 등을 직접 수정합니다. 종류를 고르면 해당 종류에 맞는 열을 제공합니다. 예를 들어 카드에서는 결제일·결제 상태, 예금에서는 잔액·이율·만기일, 퇴직연금에서는 월 납입액·첫 납입일을 수정합니다.
- 복잡한 대출 조건과 표에 없는 항목은 **상세 수정**에서 기존 입력 양식을 사용합니다. **변경 목록에 담기**를 누르면 다른 내역과 함께 저장할 대기 목록에 들어갑니다.
- 수정한 셀과 행을 표시하고 이전 값도 보여줍니다. 행별 **되돌리기**, 전체 **변경 취소**, **변경 N건 저장**을 제공합니다. 검색·종류·페이지·앱 내부 메뉴를 바꿔도 대기 중인 수정은 유지합니다.
- 현재 보이는 행에 한정하지 않고, 다른 종류·페이지에서 수정해 둔 모든 행을 한 번의 기존 계정별 PUT 요청으로 저장합니다. 일부 항목이 잘못되면 전체 저장을 중단합니다. 저장에 실패하면 대기 값이 남습니다.
- **최신 내역 불러오기**는 서버 데이터를 다시 읽으며 대기 중인 수정을 유지합니다. 대기 수정과 무관한 최신 필드 변경은 보존하고, 같은 필드가 다른 곳에서 바뀌면 자동 덮어쓰기를 거부합니다. 원본이 삭제된 대기 변경은 별도로 취소할 수 있습니다. 서버의 계정별 revision 검사도 그대로 적용합니다.

## 새 내역 등록

**새 내역 등록** 탭에 기존 11개 시작 항목, 입력 종류 전환, 저장 후 계속 입력, 최근 입력 목록을 유지합니다. 새로 등록한 내역은 기존과 같이 해당 양식의 저장 버튼으로 즉시 저장합니다. 최근 입력의 수정 버튼은 기존 내역 수정 작업공간의 대기 목록으로 연결합니다.

## 저장과 금액 숨김

대기 수정은 현재 브라우저 메모리에만 있습니다. 서버·로컬스토리지·백업에 별도 초안 사본을 저장하지 않으며 새로고침·창 닫기 시 사라집니다. 미저장 수정이 있으면 브라우저의 페이지 이탈 확인을 요청합니다. 금액 숨김 상태에서는 표에 원화 금액 입력값을 렌더링하지 않고, 금액 표시를 켠 후 금액·상세를 수정하도록 합니다. 숨김 전 대기 수정은 메모리에 유지합니다.

기존 데이터 구조, 인증, 저장 API와 검증을 사용합니다. 자동 계산 대출의 원금·이자는 기존 검증기에서 재계산하며, 대출의 다음 납부일과 매월 납부일은 별개로 편집합니다. 잔액 수정은 과거 입출금이나 상환 기록을 자동 생성하지 않습니다. DB 마이그레이션과 외부 라이브러리 추가는 없습니다.

## 검증 범위

여러 종류의 일괄 저장, 잘못된 값과 저장 실패 시 초안 보존, 대출 상세 편집과 파생 상환액, 검색·페이지·화면 전환, 금액 숨김, 행별 복원, 동시 수정·삭제 충돌, 입력값 이스케이프와 기존 등록 흐름을 검증했습니다. 전체 자동 테스트 152개 및 Worker 빌드·문법 검사, 실제 API와 SQLite를 이용한 다중 행 저장 검사를 통과했습니다.

브라우저 미리보기는 관리형 포트 중계가 준비되지 않아 시각 검증을 완료하지 못했습니다. 별도 소유자 전용 브랜치 미리보기에 배포하며 원래 운영 사이트는 바꾸지 않습니다.
