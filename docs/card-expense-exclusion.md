# 카드 청구액에 포함 · 중복 제외

카드로 결제한 지출을 상세하게 기록하면서 이미 등록한 카드대금과 두 번 합산하지 않도록 하는 옵션입니다. 예를 들어 카드 청구 100만 원에 통신비 6만 원이 포함돼 있다면, 통신비의 결제 방식을 **카드 청구액에 포함 · 중복 제외**로 지정합니다. 통신비 내역은 남고 총지출은 100만 원입니다.

- 일반 지출·예정 지출·고정지출의 추가와 수정 화면에서 결제 방식을 선택합니다. 수입에는 이 옵션을 적용하지 않습니다.
- 통합 입력·수정의 기타 지출과 고정지출 셀에서도 변경할 수 있습니다.
- 수입·지출·예정 거래·고정지출 목록에서 지출 항목을 선택하고 **카드 청구액에 포함 · 중복 제외**로 일괄 변경합니다. **계좌 결제 · 별도 지출**로 되돌리면 그 지출을 다시 합산합니다. 수입과 자산을 함께 선택했을 때에는 해당 일괄 작업을 제공하지 않습니다.
- 중복 제외한 내역은 기록과 검색에 남고, 지출 계획·예산·달력·월말 및 급여일 전망에서 별도 출금으로 다시 차감하지 않습니다. 통계에서는 금액과 상세 내역을 중복 제외 항목으로 표시하고 지출 합계에서 제외합니다.
- 실제 카드 청구액과 결제일은 카드 청구에 별도로 입력해야 합니다. 이 옵션은 카드 청구·카드 부채·현재 예금 잔액을 자동 생성하거나 변경하지 않습니다.
- 예정 거래의 **예상 반영/예상 제외**는 별도 설정입니다. 카드 청구 중복 제외를 해제하려면 결제 방식을 계좌 결제로 바꿉니다.

기존 일반 지출은 계좌 결제 방식으로 유지하며 내역을 자동으로 분류하거나 변경하지 않습니다. 기존 `cashflow` 레코드에 `paymentSource`를 저장하고 예전 클라이언트가 필드를 생략한 경우 같은 ID의 기존 설정을 보존합니다. 백업 왕복과 계정별 revision 검사를 유지하며 DB 마이그레이션은 없습니다.

계산·달력·월말 및 급여일 전망·통계의 일치, 기존 데이터의 기본값, 명시적 되돌리기, 잘못된 값의 저장 거부, 구버전 클라이언트의 설정 보존, 계정 분리, 신규/통합 수정과 실제 SQLite/API를 통한 일괄 변경을 테스트합니다. 운영 DB에 테스트 데이터를 입력하지 않습니다. 실제 브라우저 화면 배치는 관리형 미리보기 연결 제약으로 검증하지 못했습니다.
