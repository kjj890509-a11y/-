- [Stripe 열 편집](https://mobbin.com/flows/aa9bdbef-5fec-47fd-96ef-c1f4ac4c337f?tab=screens&utm_source=chatgpt&utm_medium=ai-assistant&utm_source_platform=mcp): 열별 표시 체크, 현재 열 목록, 실제 표 반영.

모든 참조는 실제 MCP 이미지로 확인했다. 저장된 보기, 머리글 직접 드래그·너비 조절, 옆 상세 패널, 카드 복제는 사용자 요청에 맞춘 추가 기능이다. Stripe의 결제 처리·환불·이의 제기 업무나 제품 전체를 복제한 것은 아니다. 모아의 직접 입력 금융 원장에 맞춰 상태와 작업을 정의했다.

## 구현 범위와 사용

- 수입·지출 메뉴의 **전체 내역**에서 모든 카테고리를 함께 조회한다. 주식·예금·퇴직금·대출·카드·수입지출·고정지출·예정 거래에도 같은 표를 제공한다.
- 상태 칩과 검색, 카테고리·기관·구분·반복·날짜·금액 범위를 AND로 적용한다. 기존 월 조회 화면은 해당 월 내역을 대상으로 한다.
- 최근 등록순/오래된 등록순, 날짜 최신/오래된순, 금액 높은/낮은순, 이름순, 각 열 제목 정렬을 제공한다. 등록순은 기존 배열의 추가 순서를 이용한다. 과거 데이터의 생성·수정 시각을 만들어내지 않으며, 전체 내역은 날짜 최신순을 기본값으로 사용한다.
- 체크박스로 현재 페이지 전체 또는 개별 행을 선택한다. 선택 내역 CSV, 삭제, 카드 결제 상태 변경, 수입지출 예상 포함/제외를 수행한다. 삭제는 선택 건수를 보여주고 확인하며, 취소 시 기록을 바꾸지 않는다.
- 머리글 손잡이 또는 열 설정 창에서 열을 드래그한다. 키보드 사용자는 열 설정의 위/아래 버튼을 사용한다. 열 너비는 경계선 드래그 또는 좌우 방향키로 조절한다. 최소 한 열은 남긴다. 열 숨김·행 간격·페이지당 20/50/100개도 설정한다.
- **배치 저장**으로 열 설정을 계정에 보관한다. **보기 저장**은 이름과 현재 필터·정렬·열 배치를 저장한다. 보기는 카테고리별 최대 12개이며 삭제할 수 있다. 행 선택과 현재 페이지는 저장하지 않는다.
- CSV는 현재 페이지에 한정하지 않고 현재 필터·정렬에 맞는 모든 결과, 또는 선택 행을 내보낸다. 표시한 열과 금액 숨김을 반영하며 수식으로 해석될 문자열을 이스케이프한다.
- 항목명이나 상세 버튼은 옆 패널을 열고 수정 창으로 이어진다. 금액 숨김이나 화면 갱신 시 열어 둔 상세 패널의 금액도 제거한다.
- 맞춤 대시보드는 바로 손잡이를 드래그하거나 방향키로 이동할 수 있다. 카드 추가·복제·기본/넓은 너비·조건 수정·제거를 제공하며 첫 변경부터 저장/취소 도구를 표시한다. 실제 잔액을 변경하는 기능과 분리한다.

## 저장과 호환성

`GET/PUT /api/preferences`, D1 `view_preferences` 테이블(`drizzle/0002_view_preferences.sql`). Sites 인증 계정 ID별 분리, 동일 출처 검사, 입력 제한, revision 충돌 검사를 적용한다. 키·금액 원장을 이 테이블에 복사하지 않으며 보기 이름·검색어·필터 조건은 계정의 비공개 설정이다. 기존 portfolio API·데이터 형식·계산 엔진은 그대로다. 보기 설정은 기존 금융 JSON 백업과 별도이다. 구버전 클라이언트의 자산 저장이 보기를 덮어쓰지 않는다.

## 검증

전체 Node 테스트 119개 통과. 실제 SQLite와 portfolio/preferences API를 통해 보기 저장의 데이터 분리, 수정 충돌, 선택 항목 일괄 변경·삭제 취소·CSV·상세 패널 금액 숨김을 확인했다. 필터·날짜·등록·금액 정렬·열 드래그/숨김·보기 실패 처리와 편집 버튼 없는 대시보드 드래그·복제·너비·저장/취소를 검증했다. 표 머리글의 직접 드래그·키보드 너비 조절까지 최종 전체 검사에 포함했다. 별도 jsdom 실행에서 19개 경로·6개 메뉴·7개 유형 저장과 예정 거래·차트·금액 숨김·통합 검색을 확인했다. 빌드(25개 로컬 자산), Worker 구문 검사와 diff 검사를 통과했다. 관리형 미리보기의 알려진 relay 연결 실패로 실화면·모바일 시각 비교는 아직 검증하지 못했다. DOM과 SQL 테스트를 브라우저 캡처 검증으로 표현하지 않는다.
