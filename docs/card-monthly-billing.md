# 내 카드와 월별 청구

카드 청구 화면에서 **카드 등록**으로 이름과 기본 결제일을 한 번 저장합니다. 이후 **내 카드 · 월별 청구**의 결제 월을 고르고 청구액만 입력한 뒤 **변경 N건 저장**을 누릅니다. 결제일과 완료 상태도 같은 표에서 바꿀 수 있습니다. 날짜가 없는 달의 기본 결제일은 말일입니다.

기존 청구를 처음 연결할 때에는 아래 전체 내역의 **내 카드로 등록**을 사용합니다. 새 카드로 등록하거나 이미 등록한 카드를 선택해 해당 청구 한 건을 연결합니다. 금액·결제일·완료 상태·메모·ID는 유지하며 같은 이름의 다른 청구를 자동으로 연결하지 않습니다.

- 카드 기본 정보는 계정별 포트폴리오 JSON의 `cardAccounts`에 `{id,name,day,note,archived}`로 저장합니다. 번호나 CVC는 받지 않습니다. 카드 등록 자체는 청구액·부채를 만들지 않습니다.
- 청구는 기존 `cards`에 저장하고 선택적으로 `cardAccountId`로 연결합니다. 결제 월은 `dueDate`의 연월입니다. 같은 등록 카드의 같은 결제 월에는 한 건만 저장하며, 수정은 기존 청구 ID를 유지합니다. 연결하지 않은 예전 내역은 원래대로 사용할 수 있습니다.
- 새 달은 미입력 상태로 시작하며 지난달 금액을 복사하거나 추측하지 않습니다. 입력한 0원과 미입력을 구분합니다. 여러 카드·결제 월의 대기 변경을 한 번에 저장합니다. 검색 화면을 오가거나 저장에 실패해도 방문 중 대기 값은 메모리에 남으며 새로고침 시에는 사라집니다.
- 잘못된 값이나 충돌이 있으면 전체 저장을 중단합니다. 최신 내역을 다시 불러와도 대기 값을 유지하며, 같은 청구 값의 외부 수정·추가·삭제를 자동으로 덮어쓰지 않습니다. 행별 되돌리기와 전체 변경 취소를 제공합니다.
- 이름과 기본 결제일을 고쳐도 이미 저장된 청구는 바꾸지 않습니다. 이미 작성 중인 새 청구의 기본 날짜도 유지됩니다. 카드 관리의 **보관/복원**은 가역적인 표시 설정이며 기존 청구를 삭제하지 않습니다. 보관한 카드의 새 달 입력은 복원 후 이용합니다.
- 저장된 청구는 기존 부채·예산·달력·기간 분석 계산을 그대로 사용합니다. 결제 완료 표시는 예금 잔액을 자동으로 차감하지 않습니다. 대기 값은 저장하기 전까지 합계에 포함하지 않습니다.

## 기존 클라이언트와 백업

포트폴리오 버전은 1을 유지합니다. 옛 백업은 내 카드 목록이 없는 상태로 열리고, 새 백업에는 카드 기본 정보와 연결이 포함됩니다. 이전 클라이언트가 전체 저장에서 새 필드를 생략하면 서버가 저장된 카드 기본 정보와 기존 청구의 연결을 보존합니다. 명시적으로 카드 목록을 비운 백업 복원은 기존 복원 동작을 따릅니다. 인증·동일 출처·계정별 revision 검사는 유지하며 DB 마이그레이션은 없습니다. 운영 사이트와 계정 저장소를 그대로 사용하고 예시 데이터를 넣지 않습니다.

## 저장한 보기 삭제

저장한 보기 이름 옆 **×**에서 바로 삭제합니다. 전체 보기는 기본 보기이므로 삭제 버튼이 없습니다. 기존의 **보기 저장 → 이 보기 삭제**도 지원합니다. 삭제는 계정별 `/api/preferences`에서 해당 보기만 지우며 금융 내역이나 자산 기록은 바꾸지 않습니다. 저장 실패 시 보기와 선택 상태를 유지합니다.

## 검증

기존 검사와 신규 검사 총 160개, Worker 빌드 및 문법·diff 검사를 통과했습니다. 실제 API/SQLite를 사용하는 DOM 검사에서 카드 한 번 등록 후 서로 다른 두 달의 청구를 저장하고, 보기 삭제 전후의 포트폴리오가 동일한지 확인했습니다. 달 말일·윤년, 0원/미입력, 중복 방지, 기존 내역 연결, 통합 수정에서의 연결 보존, 카드 보관·복원, 저장 실패·경합, 구버전 저장과 백업 호환을 검증합니다. 실제 브라우저 화면 배치 검증은 관리형 미리보기 연결 제약으로 완료하지 못했습니다.
