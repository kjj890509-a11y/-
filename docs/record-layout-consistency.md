# 목록 정렬과 드래그 일관성

열 제목의 점 9개가 절대 위치로 제목과 겹쳤고, 통합 수정표는 금액 아래 같은 설명을 반복했습니다. 일반 내역 목록에는 드래그가 연결돼 있었지만 대출 카드·월별 카드 입력·통합 수정표는 서로 다른 구현이라 이동 기능이 없었습니다.

이번 변경은 제목과 드래그 손잡이를 별도 공간에 배치하고, 금액 열의 제목·입력값을 오른쪽에 정렬하며, 반복되는 금액 보조 문구를 제거합니다. 수정 중인 이전 값은 남겨 비교할 수 있습니다. 헤더 높이와 행 관리 버튼의 크기를 맞추고 비어 있는 표의 열 수를 보정합니다.

| 목록 | 행 이동 | 열 이동 | 저장 |
|---|---|---|---|
| 전체 내역·예정 거래·주식·예금·퇴직금·수입지출·고정지출·카드 전체 내역 | 점 9개, 위아래 방향키 | 헤더 점 9개, 좌우 방향키 | 기존 배치 저장 |
| 통합 입력·수정의 전체 및 종류별 표 | 점 9개, 위아래 방향키 | 헤더 점 9개, 좌우 방향키 | 표의 배치 저장 |
| 대출 카드와 홈 부채 상세의 대출 카드 | 점 9개, 위아래 방향키 | 해당 없음 | 대출 목록의 배치 저장 |
| 내 카드 월별 청구 입력 | 점 9개, 위아래 방향키 | 헤더 점 9개, 좌우 방향키 | 월별 입력 표의 배치 저장 |

통계·달력·상환 예상처럼 날짜 순서가 계산 의미를 갖는 결과표는 이 저장 배치와 별개입니다. 기존 맞춤 대시보드의 카드 배치 기능은 유지합니다.

배치는 `/api/preferences`의 계정별 설정에만 저장합니다. 신규 표의 범위를 각각 검증하고, 예전 클라이언트가 새 범위를 생략해도 보존합니다. 명시적으로 빈 배치를 저장하면 초기화합니다. 계정·출처·revision 검사와 기존 보기 설정을 유지하며 금융 데이터의 금액·날짜·순서나 자산 기록은 배치 저장으로 바꾸지 않습니다. DB 마이그레이션은 없습니다.

일부 행만 검색·표시한 상태에서 이동하면 보이지 않는 행의 위치를 유지합니다. 드래그한 뒤 다시 그려도 임시 수정은 항목 ID에 따라 유지합니다. 배치 저장 실패 시 변경된 순서를 남기고 오류를 표시합니다. 드래그 모듈 연결에 실패하면 조용히 무시하지 않고 방향키 대안을 안내합니다. 다른 페이지로 옮기거나 다시 그릴 때 기존 드래그 인스턴스를 해제합니다.

자동 검증은 모든 통합 수정 카테고리의 헤더/본문 열 키 일치, 행·열 이동 후 수정값 보존, 저장/재조회, 검색 중 숨은 행 위치, 대출·월별 카드 입력 및 홈 부분 전환의 드래그 연결, 실제 SQLite/API의 사용자 격리·구버전 호환·잘못된 키 거부·금융 데이터 불변을 포함합니다. 실제 브라우저에서의 픽셀 배치는 미리보기 포트 릴레이 연결 제약으로 확인하지 못했습니다.
