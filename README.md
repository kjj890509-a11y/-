# 모아 · 나의 자산관리

주식, 대출, 퇴직금, 예금, 카드 결제예정액을 한곳에서 관리하는 한국어 개인 자산 대시보드입니다.

## 기능

- 총자산, 총부채, 순자산, 자산 구성 비율
- 주식 계좌·종목별 매입금액, 총평가액, 평가손익, 수익률
- 대출별 잔액, 적용 연 이율, 월 상환 원금, 월 이자 합계, 12개월 전체·대출별 예상 잔액과 이자표, 상환 방식, 매월 상환일
- 월별 고정지출: 항목별 금액·납부일·시작월·종료월·결제 방식, 선택한 월의 합계
- 퇴직금·퇴직연금 현재 금액·기준일, 회사 월 납입액과 매월 납입 일정
- 예금별 잔액, 연 이율, 만기일, 세전 예상 이자
- 카드사별 결제예정액, 결제일, 결제 상태
- 월급(실수령액), 기타 수입, 기타 지출: 금액·날짜·메모와 1회/매월 반복
- 월별 총수입, 대출·카드·계좌 고정지출·기타 총지출, 남는 예상 금액
- 월급날 기준 예상 예금·총자산·부채·순자산, 다음 월급날 요약 및 최대 12회 조회
- 예정 입출금: 특정 미래 날짜의 추가 지급·수입·지출, 예상 계산 포함·제외 전환
- 입출금 캘린더, 검색, 금액 숨김, JSON 백업·복원
- 실제 내역을 바꾸지 않는 예시 보기, 모바일 화면

## 실행

Node.js 24 이상. 고정된 의존성을 먼저 설치합니다.

```sh
npm ci
npm test
npm run dev
```

개발 서버는 4173 포트에서 동작합니다. 개발용 데이터는 `.local/preview.sqlite`에 저장합니다. 로컬 확인용 계정을 주입하므로 개발 서버를 인터넷에 직접 노출하지 마세요.

```sh
npm run build
```

결과물은 `dist/server/index.js`입니다. Cloudflare Workers 호환 ESM과 D1을 사용합니다. 운영 인증과 비공개 접근은 Sites가 담당합니다. `.openai/hosting.json`의 프로젝트 식별자·DB 바인딩과 `drizzle/`의 마이그레이션을 유지해야 합니다. 단순 정적 호스팅만으로 서버 저장·인증이 동작하지는 않습니다.

## 계산 및 입력 기준

순자산 = 주식 총평가액 + 예금 잔액 + 퇴직금 − 대출 잔액 − 미결제 카드대금.

금액은 원화 정수로 입력합니다. 해외 자산은 원화 환산액을 입력합니다. 금융기관 자동 연동 없이 직접 입력·갱신합니다. 계좌 총액과 같은 계좌의 종목 금액을 함께 등록하면 중복 합산되므로 한 가지 방식으로 기록하세요.

대출 이자는 금융기관의 납부예정액을 직접 입력하거나 잔액 × 연 이율 ÷ 12로 자동 추정합니다. 자동 추정은 원 단위로 반올림하며 은행 청구액과 일수·수수료·금리 변경에 따라 다를 수 있습니다. 기존 대출은 직접 입력 방식을 유지합니다. 상환 일정은 월 원금·이자의 반복 표시이며 자동 잔액 차감이나 납부 확인은 수행하지 않습니다. 29~31일 상환일은 해당 날짜가 없는 달의 말일에 표시합니다. 카드 결제 완료는 부채에서 해당 금액을 제외하며 예금 잔액은 직접 갱신합니다.

## 데이터 보관 및 검증

운영 데이터는 서버 DB에 로그인 계정 ID별로 분리해 저장합니다. 쓰기는 로그인·동일 출처를 확인하고, 다른 기기에서 수정된 버전을 덮어쓰지 않습니다. 브라우저에는 금액 숨김 설정만 보관합니다. 실제 금융정보·개발 DB·환경변수·비밀키는 Git에 포함하지 않습니다. 백업 파일에는 금융정보가 있으므로 안전하게 보관하세요.

`npm test`는 순자산·미결제 카드 합계, 월말 상환일, 한국 시간 기준일, 입력 검증, 계정별 데이터 분리, 비로그인·외부 출처 쓰기 차단, 수정 충돌을 확인합니다.

수입·지출의 매월 반복은 시작 월부터 같은 날짜에 표시하고, 없는 날짜는 말일에 표시합니다. 기타 지출은 대출 상환·카드 결제와 겹치지 않게 등록합니다. 수입·지출은 월 흐름 계산에 반영되며 예금·순자산 잔액을 자동 변경하지 않습니다. 이전 버전의 내역과 백업에는 빈 수입·지출 목록을 추가해 호환합니다.

## 수입·지출 계획·자산 기록·자산 전망

- **수입·지출 계획**: 월별 지출 한도와 저축 목표를 저장합니다. 등록된 월간 계획 지출과 잔여 예산을 표시합니다. 결제 완료 카드도 해당 월의 계획 지출에 포함하므로 결제 상태를 바꿔도 예산 사용분이 사라지지 않습니다. 실제 거래내역과 자동 대조하는 소비 분석은 아닙니다.
- **자산 기록**: 자산 내역을 저장할 때 서버가 그달의 기준일과 잔액을 자동 기록합니다. 기록일이 월말이 아니면 월말 실적으로 표시하지 않습니다. 저장이 없는 달의 기록을 추정해서 만들지 않습니다. 과거 월말 금액은 직접 입력할 수 있고, 수동 기록은 이후 자산 수정으로 덮어쓰지 않습니다. 미래 날짜를 실제 기록으로 저장할 수 없습니다.
- **자산 전망**: 현재 입력 잔액을 오늘 기준으로 간주하고 오늘 이후 등록된 일정으로 향후 12개월의 월말 예금·부채·순자산을 계산합니다. 주식 평가액과 연 이율은 고정하고 퇴직연금에는 등록한 회사 월 납입액을 더합니다. 월별 예상 이자는 입력 방식과 관계없이 매달 상환 전 잔액 × 연 이율 ÷ 12로 계산합니다. 원금을 상환하면 다음 달 예상 이자가 줄어듭니다. 원리금균등은 최초 잔액·이율로 추정한 이자와 등록 원금의 합계를 월 납입액으로 유지하고, 원금균등은 등록한 원금을 유지합니다. 대출 원금 상환액은 잔액까지만 반영하고 상환 완료 후 납부를 중단합니다. 카드 결제는 예금과 미결제 부채에서 함께 차감합니다. 결제일이 오늘이거나 지난 미결제 카드는 날짜를 조정하기 전까지 부채로 남깁니다. 새로운 카드 청구와 미등록 지출은 예상하지 않습니다.

월별 정보는 기존 계정별 JSON 데이터와 같은 저장소에 보관되며 기존 내역을 위한 별도 DB 변경은 없습니다. 이전 클라이언트에서 신규 필드를 생략해도 서버가 예산·자산 기록을 유지합니다. JSON 백업에 수입·지출 계획과 자산 기록도 포함됩니다.

디자인은 Mobbin MCP에서 확인한 금융 대시보드 패턴을 참고했습니다. 상세 근거는 [디자인 참고 기록](docs/design-references.md)에 있습니다.

## 고정지출과 대출 이자

고정지출은 시작월부터 종료월까지 매월 적용합니다. 시작·종료월을 포함하며 종료월이 비어 있으면 계속 반복합니다. 납부일이 해당 월에 없으면 말일로 표시합니다. 계좌 결제 고정지출은 수입·지출, 수입·지출 계획, 캘린더, 자산 전망 자산에 추가됩니다. 카드 청구액에 포함되는 고정지출은 분석용 합계에만 포함하고 등록한 카드 결제액과 중복 합산하지 않습니다. 이 방식은 카드 청구액을 별도로 등록해야 하며, 미등록 카드 청구를 새로 추정하지 않습니다. 같은 항목을 기타 지출에도 중복 입력하지 마세요.

대출관리의 '현재 납부 이자 합계'는 대출별 현재 납부 이자의 합계입니다. 직접 입력한 은행 청구액은 그대로 보관하며, 월별 예상 이자는 모든 대출을 남은 잔액과 등록 이율로 다시 계산합니다. 대출 관리는 전체 남은 잔액과 매월 납입액을 먼저 보여주고, 대출별 카드에서 남은 잔액·월 납입액·납입일을 확인합니다. 카드의 '상환 조건·관리'를 펼치면 원금·이자·이율·상환 방식·메모와 수정·삭제가 나옵니다. '월별 잔액 보기'는 해당 대출의 12개월 예상을 펼칩니다. 전체 또는 특정 대출을 선택할 수 있고, 각 월을 펼치면 상환 전 잔액·상환 원금·예상 이자·총 납입액을 볼 수 있습니다. i 버튼은 잔액 차감과 납입액의 계산식을 보여줍니다. 오늘이나 이미 지난 상환일은 현재 잔액에 반영된 것으로 간주해 첫 달에 다시 차감하지 않으며, 월말 자산 예측과 같은 기준을 사용합니다. 실제 상환 이력을 변경하지 않습니다. 완납한 대출은 월 원금·이자 합계에서 제외하고, 향후 원금은 잔액까지만 차감한 뒤 이자도 중단합니다. 이자는 대출잔액을 줄이지 않으며, 등록 원금 상환액이 0이면 잔액은 유지됩니다.

이전 백업의 고정지출 목록은 빈 목록으로 호환하고, 이전 화면이 고정지출이나 대출 이자 계산 방식을 보내지 않아도 서버가 기존 값을 유지합니다. 별도 DB 마이그레이션 없이 계정별 JSON에 저장합니다.

## 급여일 잔액

'수입·지출'에서 구분을 월급으로 등록한 날짜와 실수령액을 사용합니다. 오늘 이후 향후 1년 안의 월급일 중 최대 12회를 보여주며, 매월 반복과 월말 날짜 보정을 지원합니다. 같은 날 여러 월급이 들어오면 하나의 월급일로 합칩니다. 기준 월급을 선택하면 조회할 날짜만 좁히고 실제 자산 계산에는 다른 월급·수입도 모두 포함합니다.

각 예상치는 현재 입력 잔액에서 오늘 이후부터 월급날 당일까지의 등록 수입·지출, 계좌 고정지출, 미결제 카드, 대출 원금·이자를 반영한 하루 종료 잔액입니다. 당일 원금·카드 결제는 예금과 부채를 함께 줄여 순자산에서 중복 차감하지 않습니다. 현재 예금과 누적 수입·지출, 월급날 당일 내역을 함께 보여줍니다. 대시보드에도 다음 월급날의 예상 순자산을 표시합니다.

오늘 일정은 현재 잔액에 이미 반영된 것으로 간주하며 오늘 급여를 다시 더하지 않습니다. 주가·환율·퇴직금 평가액 변동, 새 카드 청구, 휴일에 따른 급여일 이동은 자동 반영하지 않습니다. 월급이 없거나 미래 월급일이 없으면 등록 안내를 표시합니다. 월말과 월급날 예상은 같은 날짜별 계산을 사용하며 실제 자산 기록을 변경하지 않습니다.

## 미래 예정 입출금

'예정 입출금'에서 상여금·환급금·추가 지급액 또는 여행비·경조사비 등의 항목명, 금액, 예정일, 메모를 등록합니다. 새 일정은 내일 이후 날짜를 기본으로 하며 일회성으로 저장합니다. '수입·지출'의 일회성 기타 수입·기타 지출과 같은 내역을 관리하므로 기존 일회성 내역도 보이고, 다른 화면에 중복 등록할 필요가 없습니다. 정규 월급과 매월 반복 항목은 기존 화면에서 관리합니다.

확실하지 않은 일정은 '예상에서 제외'로 보관했다가 포함으로 전환할 수 있습니다. 제외한 항목은 목록·수정 화면에는 유지되지만 수입·지출 계획·캘린더·월급날·자산 전망 합계에는 들어가지 않습니다. 예정일 당일부터 계산에 포함되며 그보다 앞선 월급날에는 미리 합산하지 않습니다. 실제 입출금이 발생하기 전에는 현재 예금 잔액을 바꾸지 않습니다. 오늘·지난 날짜는 현재 잔액에 이미 반영된 것으로 간주하며, 과거 내역은 별도 기간 선택으로 확인합니다.

이 기능은 기존 cashflow 목록에 저장하고 추가 테이블을 만들지 않습니다. 이전 내역·백업은 기본적으로 예상에 포함하며, 이전 화면이 포함 여부를 보내지 않아도 서버가 기존 제외 설정을 유지합니다. 포함 여부는 JSON 백업에도 저장됩니다.


## 통합 통계와 상환 기록

통합 통계에서 연간·월간·직접 지정한 기간을 조회하고, 은행·특정 항목·이름 또는 메모로 좁힙니다. 시작일과 종료일을 모두 포함하며 월별 그래프, 월별 합계, 항목별 합계와 상세 내역을 제공합니다. 카드 청구액에 포함한 고정지출은 따로 표시하고 현금 지출 합계에서는 제외합니다.

과거 대출은 통계의 상환 기록 추가에서 입력한 실제 원금·이자를 집계하며, 현재 잔액에서 과거 상환액을 역산하지 않습니다. 오늘 이후 대출은 현재 등록 조건으로 계산한 예상 상환으로 구분합니다. 상환 기록은 계정별 JSON의 loanPayments에 저장하고 현재 대출잔액을 자동 변경하지 않습니다. 이전 클라이언트가 이 필드를 생략해도 보존합니다.

## AI 상환 상담

상환 조건 → 그래프 비교 → AI 상담의 세 단계로 진행합니다. 매월 추가상환 예산·한 번 추가상환할 금액·유지할 예금과 12/24/36개월을 설정하면 API 호출 없이 높은 금리 우선과 적은 잔액 우선을 비교합니다. 상담 단계에서 보유한 OpenAI API 키를 비밀번호 입력칸에 연결하고 AI 상담받기를 누르면 계정 소유의 서버 자산 요약과 계산 결과로 OpenAI Responses API에 상담을 요청합니다. 추천된 상환안의 대출·예금·순자산 그래프를 비교 단계에서 확인할 수 있습니다.

API 키는 탭 메모리에서만 유지하고 서버 DB·localStorage·백업에 저장하지 않습니다. OpenAI 요청은 store:false이며 API 프로젝트의 사용량으로 청구됩니다. 기본 모델은 공식 빠른 시작 문서의 gpt-6-astra이고 모델 입력값을 바꿀 수 있습니다. API 키 또는 모델 접근 오류·사용 한도·불완전 응답을 표시합니다. 실제 API 연결은 사용자가 키를 입력한 뒤 확인할 수 있습니다.

추가 원금 상환은 예금과 부채를 함께 줄이고, 이후 절감되는 이자가 순자산 차이가 됩니다. 추가상환은 보유 예금과 유지액으로 제한하며, 중도상환수수료·금리 변경·등록되지 않은 지출은 계산에 포함하지 않습니다. 상담과 비교는 실제 대출 정보를 자동 수정하지 않습니다.

## 정보 표시 방식

주요 금액과 그래프를 먼저 보여주고 통계 상세표·자산 전망표·기록 목록은 펼쳐서 확인합니다. 계산 기준과 입력 도움말은 항목 옆의 i 버튼으로 큰 글씨의 모달에서 읽습니다. 통계 기간과 조회 조건은 별도 모달에서 설정하며, 변경 중에도 모달과 선택값을 유지합니다. 조회·계산·상담 반영 결과는 토스트로 알립니다. 금액 숨김이나 화면 변경 시 이전 설명 모달의 금액도 지웁니다.


## 회사의 퇴직연금 월 납입액

퇴직금 항목의 추가·수정에서 현재 금액과 별도로 회사 월 납입액을 입력합니다. 금액이 0원보다 크면 첫 납입 예정일을 설정하며, 그 날짜부터 매월 같은 날 적립하는 것으로 예상합니다. 29~31일이 없는 달에는 말일에 반영합니다. 월 납입액을 0원으로 바꾸면 향후 적립 예상을 중단합니다.

회사 납입은 오늘 이후 일정만 월말·월급날 예상 퇴직연금과 순자산, 대시보드 그래프, AI 상환 비교에 반영합니다. 오늘이나 지난 납입을 현재 금액에 다시 더하지 않고, 현재 금액·자산 기록·예금 잔액을 자동 변경하지 않습니다. 회사가 연금 계좌에 직접 납입하므로 생활비 수입·지출과 예산에는 합산하지 않으며 대출 추가상환에 사용할 예금으로도 취급하지 않습니다. 운용 수익률과 납입액 변동은 추정하지 않습니다.

설정은 기존 계정별 퇴직금 항목의 monthlyContribution과 contributionDate에 저장하고 백업에도 포함합니다. 이전 백업은 월 납입액 0원으로 호환하며, 이전 클라이언트가 설정을 생략해 저장해도 서버가 같은 항목의 기존 설정을 보존합니다. 별도 DB 마이그레이션은 없습니다.

## 맞춤 대시보드

`내 대시보드 → 화면 편집`에서 카드를 추가하고 제목·표시 방식·은행·항목·검색어·집계 기준을 설정합니다. 손잡이를 드래그하거나 방향키·앞뒤 버튼으로 정렬하고 `화면 저장`으로 계정에 보관합니다. 16개까지 추가할 수 있으며, 같은 종류의 카드를 여러 개 두어 은행별 대출이나 특정 지출을 나란히 비교할 수 있습니다. `기본 구성`과 `취소`는 저장 전 되돌리기입니다. 카드 제거는 원본 금융내역을 삭제하지 않습니다.

기간 통계와 현재 잔액·미래 전망은 카드 상단의 기준일로 구분합니다. `이번 달`·`올해`는 달력에 따라 이동하고, 직접 지정한 기간은 유지됩니다. 통합 통계의 `대시보드에 추가`는 조회 중인 조건과 기간으로 카드를 만듭니다. 편집 후 저장해야 새로고침하거나 다른 기기에서도 구성이 유지됩니다. 짧은 기간(62일 이내)은 일별, 긴 기간은 월별 금액을 표시합니다.

완료 기록(대출 상환 기록·결제 완료 카드), 등록 일정(수입·지출·회사 연금 납입·미결제 카드), 미래 대출 상환 예상을 구분해 조회할 수 있습니다. 회사 연금 납입액은 별도 합계이며 예금 수입·지출에 포함되지 않습니다. 과거에 반복 일정이 있었다는 사실은 실제 입출금 완료를 뜻하지 않습니다.

배치·조건은 `dashboard` 필드로 계정별 JSON에 저장하고 백업에 포함합니다. 화면 저장 전용 PUT 요청은 `{dashboard, revision}`만 받으며 기존 금융내역을 서버에서 유지하고 새 자산 기록을 생성하지 않습니다. 이전 클라이언트가 이 필드를 생략하면 기존 설정을 유지합니다. 익명·다른 출처·오래된 버전의 쓰기는 거부합니다.

드래그에는 GitHub의 [SortableJS/Sortable](https://github.com/SortableJS/Sortable) npm `sortablejs@1.15.7` (MIT)을 사용합니다. MCP 서버가 아니라 브라우저 드래그 플러그인입니다. 빌드 시 ESM과 라이선스를 같은 사이트에 포함하며 외부 CDN 스크립트·텔레메트리·추가 계정 권한이 없습니다. 편집할 때만 로드하고, 실패하면 버튼·키보드 이동을 사용합니다.

이번 변경은 계산·DOM 상호작용·계정별 저장·Worker 자산 제공을 테스트했습니다. 브라우저 검사 인프라 오류로 실제 브라우저 드래그와 모바일 화면 캡처는 검증하지 못했습니다.

기본 홈은 자산 현황, 홈의 **맞춤 대시보드** 탭은 통계 카드 편집에 사용합니다. 기존 저장된 카드·순서·기간과 드래그/키보드 조작 기능을 유지합니다.

### 남은 기간으로 대출 상환 계산

대출 추가에서 기본값인 **남은 기간으로 자동 계산**을 선택한 뒤 현재 잔액, 적용 연이율, 상환 방식, 남은 납부 횟수(거치 포함), 거치 횟수, 다음 납부일과 이후 매월 납부일을 입력합니다. 기존 대출은 수정에서 이 모드로 전환할 수 있습니다.

- 원금균등분할: `현재 잔액 ÷ (남은 횟수 − 거치 횟수)`의 정수 원금을 매회 상환합니다. 마지막 회차에 원 단위 나머지를 정산하고 이자는 매회 줄어든 잔액으로 계산합니다.
- 원리금균등: 거치 이후 납부액을 연이율·남은 회차로 계산합니다. 마지막 회차는 원 단위 차이를 정산합니다.
- 만기일시: 매월 이자만 내고 마지막 회차에 남은 원금을 상환합니다.
- 모든 이자는 `상환 전 잔액 × 연이율 ÷ 12`의 월할 추정치입니다. 은행의 일수 계산, 변동금리, 중도상환수수료와는 차이가 있을 수 있습니다.
- 입력 중 첫 납부액·원금·이자·남은 총이자·총상환액·완납 예정일을 미리 확인합니다. 상환표는 12개월, 3년, 완납까지 조회할 수 있습니다.
- 현재 잔액·남은 횟수·상환 이력은 예상표가 자동으로 바꾸지 않습니다. 상환 후 직접 갱신하세요. 다음 납부일이 지났으면 경고하며, 미갱신 잔액과 횟수를 다음 납부일부터 계산합니다.
- 기존 월 원금 직접 입력 방식과 백업을 지원합니다. 예산·달력·월별/급여일 전망·상환 비교는 같은 계산을 사용합니다.

공개 회원 서비스와 광고에 대한 제안은 [보안 설계](docs/public-service-security.md)에 정리했습니다. 현재 소유자 전용 접근 범위는 유지합니다.
